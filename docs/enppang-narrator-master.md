# 엔빵 나레이터 마스터 레퍼런스 (v0.1)

> 채널: **엔빵 | 내 돈 나눠 먹는 사람들**
> 모든 회차의 나레이션은 이 문서와 **본인 목소리 마스터 레퍼런스**를 기준으로 만든다.
> 뉴과의 `docs/narrator-voice-master.md`와 같은 역할이다. 뉴과의 기록관 설정, 후반 효과, 발음 사전은 가져오지 않았다.

**2026-11-22 확정 (사용자 결정)**

| 항목 | 결정 |
|---|---|
| 마스터 레퍼런스 | 본인 목소리로 만든다 |
| 유행어와 감탄사 | 제한 없이 쓴다 |
| 숫자 | 제약이 없다. 이 채널은 숫자가 중요하다 |
| 단정 표현 | 자유롭게 쓴다 |

## 1. 마스터 보이스

| 항목 | 값 |
|---|---|
| 마스터 보이스 | 진행자 본인 목소리 |
| 마스터 레퍼런스 | 3장의 기준 대본을 본인이 읽은 녹음 1개. **2026-11-22 녹음 완료** (원본 74.7초, 정리본 72.5초). 측정 결과는 5장 |
| 등록 위치 | `library/voice/enppang-master-myvoice/` (대본 `my-voice-reference.txt`, 설정 `preset.json`, 원본 `my-voice-original.m4a`, 정리본 `my-voice-reference.wav`와 `.mp3`) |
| 음성 파일 | 공개 저장소에 올리지 않는다. 진행자가 따로 보관한다. 작업 환경이 닫히면 이곳의 파일은 사라진다 |
| 쓰는 법 | 직접 녹음하는 회차는 녹음 전에 레퍼런스를 듣고 톤과 속도를 맞춘다. 목소리 클론으로 만드는 회차는 레퍼런스로 클론을 등록한다 |
| 회차 제작 방식 | 미정 (직접 녹음 / 목소리 클론). 어느 쪽이든 이 레퍼런스가 기준이다 |
| 뉴과 녹음과의 관계 | 뉴과용 본인 목소리 녹음(1분 5초)이 있지만, 그 대본에는 엔빵의 유행어·감탄사와 숫자를 연달아 읽는 문장이 없다. 엔빵 기준 대본으로 따로 녹음한다 |

목소리 클론으로 만들 때 알아 둘 것 두 가지.

- 뉴과 가이드(`docs/style-guide.md` 2-1)에는 유행어를 AI 음성으로 읽으면 타이밍과 억양이 살지 않아 어색하게 들린다고 적혀 있다. 본인 목소리 클론에서도 같은지는 아직 들어 보지 않았다. 어색한 대목은 그 문장만 직접 녹음해 바꿔 끼운다
- 클론으로 만든 회차는 플랫폼의 AI 표시를 켜고 설명란에 적는다 (기획서 운영 원칙 4, 뉴과 발행 방식)

| 유행어와 감탄사 | 제한 없이 쓴다. 숫자를 말하는 문장에도 쓴다 | 확정 (2026-11-22) |
| 숫자 | 한 문장에 몇 개든 쓴다 | 확정 (2026-11-22) |

| 쓰지 않는 말 (단어장 3번 목록) | 초성, 비속어 접두사, 사람·집단 비하에서 온 말, 재난·사망 대목의 유행어 | 단어장 3장 |

| 수치 확인 | 지어내지 않는다. 확인하지 못한 문장에는 ⚠️를 단다. 단정 표현이 자유로워도 이 규칙은 그대로다 | 확정 (첫 작업 지시) |
| 나레이터 인물상 | 정하지 않았다 | 미정 |

## 3. 기준 대본 (약 1분, 본인 녹음용)

공백 제외 361자, 17줄. 숫자는 모두 1화 대본에서 여러 매체가 일치한 것만 썼다.

```
치킨 한 마리, 2만 3천 원.

올해 3월, 치킨용 닭은 1킬로그램에 5,308원이었습니다.
9월에는 3,308원. 여섯 달 만에 37.7%가 빠졌습니다.
그동안 치킨값은요? 0원 내렸습니다.
와, 이거 실화?
닭값은 떡락했는데, 치킨값은 꿈쩍도 안 했습니다.

아니 근데, 내 2만 3천 원은 다 어디로 갔을까요.
치킨 가맹점 한 곳이 1년 동안 본사에 내는 마진이 평균 4,100만 원, 매출의 9.5%입니다.
배달 앱 수수료는 2.0%에서 7.8%, 가게가 내는 배달비는 1,900원에서 3,400원.
무료 배달이요? 결국 내돈내산이었거든요. 내 돈 주고 내가 산 배달입니다.

작년 영업이익률은 교촌 6.7%, BBQ 13.1%, bhc 26.8%.
헐, 같은 치킨 본사인데 네 배 차이입니다.

치킨, 잘 먹었습니다.
근데, 누가요?

그 돈을 누가 엔빵했는지, 영수증 한 장으로 보여 드립니다.
내 돈 나눠 먹는 사람들.
엔빵이었습니다.
```

## 4. 녹음하는 법

1. 조용한 방에서 휴대폰으로 녹음한다. 뉴과 레퍼런스도 휴대폰 녹음이었다
2. 3장의 대본을 평소 말하듯 처음부터 끝까지 읽는다. 틀리면 그 문장 처음부터 다시 읽고 이어 간다
3. 목소리 클론에 쓸 생각이면 같은 대본을 두세 번 읽어 2~3분으로 만든다. 뉴과 때 클론 서비스가 더 긴 녹음을 요구할 수 있다고 적어 두었다
4. 녹음 파일을 작업방에 올린다. 올린 뒤에 할 일:
   - 정리본 제작: 70Hz 이하 제거, 약한 잡음 제거, -16 LUFS (뉴과 본인 목소리 레퍼런스와 같은 처리)
   - 길이를 재서 분당 글자 수를 계산하고 5장 표를 채운다
   - 1화 대본의 길이 추정을 그 속도로 다시 계산한다

### 5-2. 녹음에서 보이는 것

- 가장 천천히 읽은 문장은 1번 가격표 훅과 7번 "와, 이거 실화?"다. 둘 다 초당 4.7음절이다
- 숫자가 많은 문장은 오히려 빨랐다. 10번 7.5, 11번 7.2, 15번 7.2로 전체 평균 6.6보다 빠르다
- 가장 긴 쉼은 1.4초다. 11번 문장 안에 있고, 길이로 보아 마지막 숫자 "3,400원" 앞으로 추정한다
- 문장 뒤의 쉼이 가장 긴 곳은 14번 뒤 0.9초(문단이 바뀌는 자리), 2번 뒤 0.9초, 7번 뒤 0.8초다

### 5-3. 확인하지 못한 것

- **소리를 들어 볼 수 없어서 발음, 억양, 잘못 읽은 곳은 확인하지 못했다.** 이 작업 환경에는 음성을 글자로 바꾸는 도구가 없다
- 대신 쉼으로 나뉜 구간 42개를 대본의 21문장에 순서대로 맞춰 보았다. 문장의 음절 수와 말한 시간의 상관계수가 0.99였고, 문장별 속도가 모두 초당 4.7~8.3음절 안에 들었다. 그래서 대본을 처음부터 끝까지 한 번 읽은 녹음으로 본다
- 3장의 톤 메모는 여전히 초안이다. 정리본을 들어 보고 본인 느낌으로 고친다

### 5-4. 음질과 정리본

| 항목 | 원본 | 정리본 |
|---|---|---|
| 파일 | `my-voice-original.m4a` (AAC, 48kHz, 모노) | `my-voice-reference.wav` (48kHz, 16비트, 모노), `.mp3` (192kbps) |
| 길이 | 74.7초 | 72.5초 |
| 음량 | -26.7 LUFS | -16.0 LUFS |
| 최고 레벨 | -2.5 dBFS | -1.9 dBTP |
| 잡음 바닥 | -70 dB | -67 dB |

- 원본은 조용하고 깨끗하다. 소리가 잘린 곳(클리핑)이 없다
- 정리본 처리 순서: 앞뒤 자르기(0.85~73.30초. 녹음을 시작하고 멈출 때의 터치 소리를 뺐다) → 70Hz 이하 제거 → 약한 잡음 제거(6dB) → 부드러운 압축(기준 -24dB, 2:1) → 음량 올리기(+14.7dB) → 제한기(최고 -2dB)
- 압축과 제한기를 쓴 이유: 원본은 순간 피크가 평균 음량보다 약 25dB 높다. -16 LUFS까지 그대로 올리면 피크가 0dB를 약 9dB 넘는다. 뉴과 나레이션 보정(`scripts/typecast_narration.py`)도 압축한 뒤 -16 LUFS로 맞춘다
- 목소리 클론을 만든다면 손대지 않은 원본을 쓸 수도 있다. 뉴과 문서(`narrator-voice-master.md` 2-3)는 클론 원본으로 효과를 입히지 않은 깨끗한 소리를 권한다
